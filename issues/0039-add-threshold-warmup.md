# 立ち上がり期間を集計から除外する

- Created: 2026-10-07
- Completed: 2026-10-07
- Branch: feature/add-threshold-warmup
- Polished: {YYYY-MM-DD}

## 目的

しきい値の判定を、負荷が立ち上がりきってからの測定結果に対して行えるようにする。

`--vcs-hatch-rate` で仮想クライアントを徐々に増やすため、試験開始直後は負荷が目標に
達していない。この期間の接続は、対象サーバーの暖機や負荷の不足の影響を受けやすく、
そのまま集計に混ぜると合否がぶれる。k6 などの負荷試験ツールが持つ warmup 相当の
除外期間を設けられるようにする。

## 現状

- `zakuro-core/src/stats.rs` の集約タスクは、受け取った接続終了イベントをすべて
  集計対象にしている
- `StatsEvent::ConnectionEnded` は接続の終了時刻を持たないため、集約側では
  「いつ終わった接続か」を判断できない
- しきい値 (`--threshold-success-rate` など) は、この集計結果に対して判定している

## 設計方針

- 接続終了イベントに終了時刻を持たせ、集約側が試験開始からの経過時間で判定できるようにする。
  時刻には単調時計 (`Instant`) を使い、系の時刻変更の影響を受けないようにする
- `StatsCollector` に除外期間 (warmup) を渡す。集約タスクは、除外期間が経過する前に
  終了した接続を集計対象から外す。接続の判定は終了時点の 1 点で決まるため、
  測定窓を「終了時刻が warmup 以降の接続」と定める
- 除外した接続数は集計結果に残す。除外が効いていることを確かめられるようにする
- `--threshold-warmup <SECONDS>` を追加する (0 以上、デフォルト: 0 で除外しない)。
  既定で除外すると、短い試験で判定対象が 0 本になりしきい値が必ず違反になるため、
  指定したときだけ有効にする
- DuckDB の `connection_lifecycle` には全接続を記録したままにする。除外は集計の話であり、
  生の記録は残す

## 完了条件

- `--threshold-warmup` に指定した期間より前に終了した接続が、集計としきい値の判定から
  外れること
- 除外した接続数がログと JSON に残ること
- 除外期間を指定しなければ、従来どおりすべての接続が集計されること
- 除外の有無と境界値 (終了時刻が warmup ちょうど) が単体テストで検証されること
- `cargo fmt --all -- --check` が通ること
- `cargo clippy --locked --workspace --all-targets --features fdk-aac -- -D warnings` が通ること
- `cargo test --locked --workspace --features fdk-aac` が通ること

## 解決方法

- `StatsEvent::ConnectionEnded` に `ended_at` (`std::time::Instant`) を追加した。単調時計を
  使うことで、系の時刻変更の影響を受けずに経過時間を判定できる
- `StatsCollector::new` に除外期間 (`warmup`) を渡すようにし、集約タスクが
  `is_counted` で「終了時刻が試験開始から `warmup` 以降か」を判定して、内側の接続を
  集計から外すようにした。除外期間が 0 の場合は常に集計する
- 除外した接続数は `StatsSummary::warmup_excluded` として持ち、ログと JSON に出す。
  ログは 0 件のときは出さない
- `--threshold-warmup <SECONDS>` を追加した (0 から 86400、デフォルト: 0)。既定で除外すると
  短い試験で判定対象が 0 本になり、しきい値が必ず違反になるため、指定したときだけ有効にした。
  JSONC の最上位でも指定できる
- `zakuro-moq` は接続単位の合否を判定しないため、除外期間に 0 を渡す
- 単体テストとして、`is_counted` の境界値 (内側 / ちょうど / 外側 / 除外期間 0) と、
  集約タスクが立ち上がり期間の接続を除外して数えることを追加した
- 到達できないシグナリング URL に対して `--threshold-warmup 60` を付けて起動し、
  接続が除外されて `judged=0` / `warmup_excluded=1` になり、しきい値が
  「判定できる接続が無い」として違反になり終了コード 1 で終わることを確認した
- README に `--threshold-warmup` の説明を追記した
